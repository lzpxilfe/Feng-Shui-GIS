# 조망 분석 (Line-of-Sight for Named Landforms)

## 왜 넣었나

안산(案山)과 조산(朝山)은 **혈에서 바라보이는 산**입니다. 이름 자체가 그렇습니다.
案은 책상처럼 앞에 놓인 것, 朝는 마주 조회하는 것입니다.

그런데 0.1.2까지 이 플러그인은 안산·조산을 **고도와 방위로만** 골랐습니다.
지정 방위 부채꼴 안에서 반경 조건을 만족하는 최고점을 집으면 그게 안산이 됐습니다.
**중간에 더 높은 능선이 가로막고 있어도 그대로 안산이었습니다.**

즉 혈에 서 있는 사람이 볼 수 없는 산에 "안산" 라벨이 붙을 수 있었습니다.
개념 정의상 성립하지 않는 상태입니다.

중국 풍수 GIS가 가시권(viewshed) 분석을 표준으로 갖추고 있는 이유가 이것입니다.
조망은 장식이 아니라 판정 요소입니다.

## 2. 무엇을 계산하나

혈에서 각 용어 지점까지의 **지형 단면을 표집해 시선이 통하는지** 봅니다.

1. 혈과 대상 지점 사이 직선을 따라 DEM을 표집합니다(양 끝점 제외, 최대 64점).
2. 관측자 눈높이(기본 1.7m)를 더한 시점에서, 각 중간 지점이 이루는 앙각을 구합니다.
3. 그중 최대 앙각이 **지형 능선선(horizon)** 입니다.
4. 대상 지점의 앙각이 그보다 크면 보이는 것입니다.

지구 곡률과 대기 굴절도 반영합니다(k=0.13). 10km에서 약 6.8m 내려앉습니다.
가까운 안산에서는 무시할 만하지만 수 km 밖 조산에서는 유의미합니다.

### 새 필드

| 필드 | 뜻 |
| --- | --- |
| `visible` | 1 = 혈에서 조망 가능, 0 = 차단, NULL = 판정 불가 |
| `los_clear` | 지형 능선선 대비 여유고(m). 음수면 그만큼 가려짐 |

`reason_ko` 끝에도 붙습니다.

> 조망=조망 차단, 1200m 지점 능선선 아래 43.2m

## 3. 점수는 바꾸지 않았습니다

**의도적입니다.**

조망을 `fs_score`에 바로 물리면 기존 사용자의 모든 결과가 조용히 달라집니다.
안산이 안 보인다고 점수를 깎을지, 얼마나 깎을지는 **근거가 필요한 판단**이고,
아직 그 근거가 없습니다.

그래서 이번 단계에서는 **사실만 기록**합니다. 사용자는 이제 "이 안산이 실제로
보이는가"를 확인할 수 있고, 필요하면 `visible = 0`으로 직접 필터링할 수 있습니다.

점수 반영은 사례 자료로 검증한 뒤에 **명시적 옵션**으로 들어가는 것이 맞습니다.

## 4. 용어별로 의미가 다릅니다

같은 계산이지만 해석 무게가 다릅니다.

| 용어 | 조망의 의미 |
| --- | --- |
| **안산·조산** | **정의적 요소.** 보이지 않으면 개념상 안산·조산이라 부르기 어렵습니다. |
| 청룡·백호 | 보조 근거. 이들은 조망보다 **위요(감싸기)** 가 핵심이므로, 안 보인다고 해서 결격은 아닙니다. |
| 주산·조종산 | 보조 근거. 배후 지형은 보이지 않아도 지맥상 기능합니다. |
| 수구 | 보조 근거. 물길 출구는 지형에 가려도 수문상 존재합니다. |

모든 용어에 대해 계산은 하되, **안산·조산 외에는 참고 정보**로 읽으십시오.

## 5. 한계

- **지형 차폐만 봅니다.** 식생, 건물, 대기 시정은 모델에 없습니다. 실제 답사 시야와
  다를 수 있습니다.
- **현대 DEM 기준입니다.** 절토·성토·댐·매립으로 지형이 바뀐 곳은 과거 조망과
  다릅니다.
- **표집 밀도의 한계.** 최대 64점이므로 아주 얇고 날카로운 능선은 놓칠 수 있습니다.
- **보인다고 안산인 것은 아닙니다.** 조망은 필요조건에 가깝지 충분조건이 아닙니다.
